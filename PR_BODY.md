Summary

- Restore VuePress v1 compatibility and avoid native builds on Windows/modern Node.
- Changes: downgrade `@vuepress/theme-blog` to v1 range, replace `node-sass` with `sass` (Dart Sass), add `cross-env` and prefix scripts with `NODE_OPTIONS=--openssl-legacy-provider` to work around OpenSSL/webpack issues on newer Node versions. Update `yarn.lock`.

Files changed

- `package.json` — downgraded theme, removed `node-sass`, added `sass` and `cross-env`, updated scripts.
- `yarn.lock` — regenerated by Yarn.
- `README.md` — added Node + install instructions.
- `.github/workflows/ci.yml` — CI checks: `yarn install` + `yarn build` on PR.

Root cause evidence

1) Package mismatch (VuePress v1 vs @vuepress/theme-blog v2) — diff from the submitted commit:

```diff
-    "@vuepress/theme-blog": "^2.3.3",
+    "@vuepress/theme-blog": "^1.3.3",
```

2) Build error on modern Node (OpenSSL / webpack) observed when building under Node 22:

```
Error: error:0308010C:digital envelope routines::unsupported
...
Node.js v22.5.1
```
(see `blog/logs/build.log`)

3) Native `node-sass` rebuild failures on Windows (node-gyp / Visual Studio requirement) caused `yarn install` to fail when node-sass was present under newer Node — replaced with `sass` to avoid native compilation.

What I changed and why

- Downgraded `@vuepress/theme-blog` to `^1.3.3` so all `@vuepress/*` packages are on v1 (matches `vuepress@^1.8.0`). This is the minimal change to restore compatibility instead of migrating to VuePress v2.
- Replaced `node-sass` with `sass` (Dart Sass) to avoid native builds and node-gyp/Visual Studio requirements on Windows/CI.
- Added `cross-env` and prefixed `dev`/`build` scripts with `NODE_OPTIONS=--openssl-legacy-provider` to work around OpenSSL/webpack incompatibilities on Node >=17/Node 22.
- Added a CI workflow to run `yarn install --frozen-lockfile` and `yarn build` on PRs to catch regressions.

Manual verification steps (what I ran locally)

```powershell
# verify HTTP response

```

Notes and follow-ups

- If the team prefers to migrate to VuePress v2, that is a larger change and should be done in a separate migration PR (I stopped at the minimal v1 compatibility fix per the ticket scope).
- I recommend switching local and CI Node to an LTS (18.x or 20.x) for long-term stability; the added `cross-env` prefix is a compatibility shim for newer Node.
